# Тренажёр по шаблонам

Локальный веб-интерфейс к файлам из `algorythms/part-1/`.

```bash
python3 web/server.py
```

Откроется на http://127.0.0.1:8765 (другой порт — `python3 web/server.py 9000`).
Зависимостей нет, только стандартная библиотека Python 3.

## Что внутри

**Теория** — полноценный markdown preview: эталон превращается в markdown
(заголовки, абзацы, нумерованные списки, ```python блоки), а тот рендерится
в документ на белом листе с чёрным текстом — как README на GitHub.
Кнопка «исходник markdown» в правом верхнем углу листа показывает тот самый
markdown, который рендерится и скачивается.

Докстроки и комментарии не показываются «как есть»: строка без отступа,
набранная капсом, становится заголовком; выровненное в столбик, ascii-схемы
и строки почти без кириллицы — блоками кода; «1. …» и «A) …» — списками;
остальное склеивается в абзацы, которые переносятся по ширине окна,
а не по 79 колонок.

**Тема** — кнопка в сайдбаре: светлая (по умолчанию) / тёмная / авто по системе,
выбор запоминается. Тему держит вся страница целиком, включая лист с теорией
и карточку задания: светлая — белый лист с чёрным текстом, тёмная — тёмный лист
со светлым. Контраст проверен в обеих: основной текст 17.8:1 и 14.7:1,
комментарии в коде и подписи — не ниже 5.6:1 (порог WCAG AA — 4.5:1).

**Исходник** — кнопка «исходник markdown» в углу листа показывает тот самый
markdown, из которого собран документ. Скачивания нет: страница и есть
результат, а исходник всегда под рукой.

**Дрилл** — задание из `-drill.py`, редактор, таймер на 5 минут и запуск тестов.

- функция выбирается чипом сверху; дриллится одна за сессию;
- при запуске собирается эталон, в котором ТВОЯ функция подставлена вместо
  эталонной, и вызываются её тесты — остальные функции берутся рабочими,
  поэтому `count_components` можно писать, не написав перед этим `DSU`;
- «что именно запускалось» под выводом показывает собранный файл целиком;
- таймер стартует с первого нажатия клавиши, останавливается на зелёных
  тестах, после 5 минут начинает считать вверх красным;
- «показать эталон» — спойлер, открывать после запуска тестов;
- черновики и история попыток (время, ✓/✗) лежат в localStorage браузера;
  точка у шаблона в списке и у функции в чипе — результат последней попытки;
- «следующая по ротации» — та функция, которую дольше всех не трогал.

## Редактор

Подсветка синтаксиса прямо в поле ввода: под кареткой лежит подсвеченный слой,
метрики у него совпадают с textarea до пикселя. Правки идут через
`execCommand("insertText")`, поэтому нативный Ctrl+Z продолжает работать.

Кнопка `python` / `typescript` в панели переключает язык редактирования —
подсветку, символ комментария и шаг отступа. Тесты в любом случае гоняет
python: дриллы написаны на нём, а ts-режим нужен, когда переписываешь шаблон
на другой язык.

| | python | typescript |
|---|---|---|
| шаг отступа | 4 пробела | 2 пробела |
| комментарий | `#` | `//` |
| отступ после | `:` | `{`, `(`, `[` |
| дедент следующей строки | `return`, `pass`, `break`, `continue`, `raise` | — |

Что умеет:

- **Enter** — держит отступ, добавляет уровень после `:` (или `{` в ts)
  и снимает его после `return` / `pass` / `break`;
- **Enter между парой скобок** — раскрывает их в три строки с курсором внутри;
- **Tab / Shift+Tab** — сдвиг выделенных строк целиком; без выделения Tab
  доводит до ближайшей позиции табуляции, а не всегда вставляет 4 пробела;
- **Backspace** в отступе снимает уровень целиком, а между пустыми скобками
  или кавычками удаляет обе;
- **скобки и кавычки** закрываются сами; выделил кусок и нажал `(` или `"` —
  обернуло; закрывающая скобка не дублируется, а проскакивает уже стоящую;
- **⌘/Ctrl + /** — закомментировать или раскомментировать выделенные строки;
- **⌘/Ctrl + Enter** — запуск тестов.

## Что переживает перезагрузку

Всё состояние лежит в localStorage браузера и восстанавливается при следующем
открытии страницы:

- открытый шаблон (он же в адресе после `#`, ссылкой можно делиться),
  активная вкладка (теория / дрилл) и выбранная функция;
- по функции на шаблон: какую дриллил последней — вернёшься к шаблону,
  откроется она же;
- черновик кода отдельно для каждой функции и история попыток (время, ✓/✗);
- прокрутка теории и режим «исходник markdown»;
- таймер: если он шёл, то после перезагрузки идёт дальше и добирает время,
  прошедшее между закрытием и открытием. Если перерыв больше получаса,
  считается, что сессия брошена: время сохраняется, но таймер стоит на паузе.

## Как это устроено

Отдельной базы нет: сервер парсит `ethalons/blockN/*-ethalon.py` и
`drill/blockN/*-drill.py` через `ast` при каждом запросе. Добавил новый
шаблон в тех же соглашениях — он появится в интерфейсе сам:

- имя файла `<имя>-ethalon.py` и `<имя>-drill.py` в одноимённых `blockN`;
- первая строка докстроки модуля: `ШАБЛОН <номер> — <название>`;
- блок `# ===...` над функцией — её разбор (в дрилле — задание);
- функция в дрилле с телом `pass` считается целью, написанная целиком
  (`TreeNode`, `build`, `is_valid_order`, `norm_sets`) — вспомогательной;
- тест для функции `foo` называется `test_foo`.

Код из редактора выполняется настоящим `python3` в отдельном процессе с
таймаутом 15 секунд. Сервер слушает только 127.0.0.1 и рассчитан на запуск
на своей машине.
