# Тренажёр по шаблонам

Локальный веб-интерфейс к файлам из `algorythms/part-1/`.

```bash
python3 web/server.py
```

Откроется на http://127.0.0.1:8765 (другой порт — `python3 web/server.py 9000`).
Зависимостей нет, только стандартная библиотека Python 3.

Онлайн-версия: **https://shayaqhmetov.github.io/algorythm-templates/**

## Две версии, один интерфейс

Страница сама определяет, где она открыта, и берёт данные оттуда, откуда может:

| | локально | GitHub Pages |
|---|---|---|
| откуда шаблоны | сервер парсит `.py` через `ast` на каждый запрос | запечённый json из `docs/data/` |
| чем гоняются тесты | python на машине, отдельный процесс | python в браузере (Pyodide в web worker) |
| первый запуск | мгновенно | ~10 МБ с cdn, дальше быстро |
| бесконечный цикл | процесс убивается по таймауту 15 с | воркер убивается по таймауту 15 с |

Собрать статику руками:

```bash
python3 web/build_static.py        # -> docs/
python3 -m http.server -d docs 8766
```

`docs/` в git не лежит — его собирает и публикует `.github/workflows/pages.yml`
при пуше в `main`. Правишь эталоны и дриллы — сайт обновляется сам, отдельную
копию контента поддерживать не надо. Перед сборкой workflow прогоняет все
эталоны: если чей-то `assert` упал, деплой не поедет.

## Что внутри

**Теория** — полноценный markdown preview: эталон превращается в markdown
(заголовки, абзацы, нумерованные списки, ```python блоки), а тот рендерится
в документ на белом листе с чёрным текстом — как README на GitHub.
Кнопка «исходник markdown» в правом верхнем углу листа показывает тот самый
markdown, который рендерится и скачивается.

Докстроки и комментарии не показываются «как есть»: строка без отступа,
набранная капсом, становится заголовком; выровненное в столбик, ascii-схемы
и строки почти без кириллицы — блоками кода; «1. …» и «A) …» — списками;
остальное склеивается в абзацы, которые переносятся по ширине окна,
а не по 79 колонок.

**Тема** — кнопка в сайдбаре: светлая (по умолчанию) / тёмная / авто по системе,
выбор запоминается. Тему держит вся страница целиком, включая лист с теорией
и карточку задания: светлая — белый лист с чёрным текстом, тёмная — тёмный лист
со светлым. Контраст проверен в обеих: основной текст 17.8:1 и 14.7:1,
комментарии в коде и подписи — не ниже 5.6:1 (порог WCAG AA — 4.5:1).

**Исходник** — кнопка «исходник markdown» в углу листа показывает тот самый
markdown, из которого собран документ. Скачивания нет: страница и есть
результат, а исходник всегда под рукой.

**Дрилл** — задание из `-drill.py`, редактор, таймер на 5 минут и запуск тестов.

- функция выбирается чипом сверху; дриллится одна за сессию;
- при запуске собирается эталон, в котором ТВОЯ функция подставлена вместо
  эталонной, и вызываются её тесты — остальные функции берутся рабочими,
  поэтому `count_components` можно писать, не написав перед этим `DSU`;
- «что именно запускалось» под выводом показывает собранный файл целиком;
- таймер стартует с первого нажатия клавиши, останавливается на зелёных
  тестах, после 5 минут начинает считать вверх красным;
- «показать эталон» — спойлер, открывать после запуска тестов;
- «построчно с эталоном» — сравнение твоего кода с эталоном, см. ниже;
- черновики и история попыток (время, ✓/✗) лежат в localStorage браузера;
  точка у шаблона в списке и у функции в чипе — результат последней попытки;
- «следующая по ротации» — та функция, которую дольше всех не трогал.

**Группа** — переключатель «все / 1 / 2 / 3 / 4» в сайдбаре. Группа N — это N-я
функция каждого шаблона; день = одна группа по всем шаблонам.

- под названием шаблона вместо имени файла показана функция этой группы;
- клик по шаблону открывает сразу её, а не ту, что дриллил там последней;
- точка у шаблона — результат этой функции ЗА СЕГОДНЯ (вчерашний зелёный
  не считается), сверху счёт «сегодня: 7 / 18»;
- у чипов функций стоят номера групп, чип выбранной группы подсвечен;
- «все» возвращает обычный режим; выбор запоминается.

## Результат прогона — по кейсам, как на LeetCode

Каждый `assert` в тесте эталона — отдельный кейс. Упавший кейс не обрывает
прогон: проверяются все, и видно, какие именно не прошли.

- сверху вердикт: **Принято**, **Неверный ответ**, **Ошибка выполнения**,
  **Синтаксическая ошибка** или **Превышено время** — и счёт «7 / 10 кейсов»;
- ряд кейсов ✓ / ✗; открывается первый упавший, остальные — по клику;
- у кейса: **ввод** (вызов, как он записан в тесте), **твой ответ** и
  **ожидалось**, stdout твоих `print` именно в этом кейсе;
- если твой код бросил исключение — тип, сообщение и **строка твоего кода**,
  а не строка собранного файла;
- комментарий эталона над `assert` становится подсказкой к кейсу, а пометка
  `(!)` — меткой «ловушка»: ради таких кейсов тесты и писались;
- `assert` внутри цикла — один кейс: «проверок в цикле: 49, прошло 12»
  и первый провал;
- если тест упал не в кейсе, а в подготовке (например, у `DSU` ещё нет `find`),
  об этом отдельная плашка, а недошедшие кейсы помечены «·».

Как устроено: при сборке запуска `assert`-ы тестов переписываются в вызовы
`_DRILL.case(...)` — через `ast`, с сохранением остального текста теста;
обвязка ловит исключения по каждому кейсу и последней строкой stdout печатает
отчёт в json. Для Pages это делается на этапе сборки, тесты в браузере
гоняются той же обвязкой.

## Сравнение с эталоном

Кнопка «построчно с эталоном» в панели дрилла (или такая же в выводе после
прогона тестов) меняет редактор на две колонки: слева твой код, справа эталон.
Esc или «назад к коду» — обратно.

- **совпало** — строка есть у обоих, фон обычный;
- **отличается** (жёлтый) — похожие строки поставлены друг напротив друга,
  отличающиеся токены подсвечены; если разошёлся только отступ — метка «отступ»;
- **нет у тебя** (красный справа) — строка эталона, которой в твоём коде нет;
- **лишнее** (синий слева) — строка, которой нет в эталоне.

Сверху счёт «совпало с эталоном: N из M» по значимым строкам эталона
и полоса прогресса; при полном совпадении — «один в один с эталоном».

Как сравнивается:

- пустые строки и строки из одного комментария не участвуют;
- «без комментариев» (включено по умолчанию) отрезает хвостовые комментарии —
  у эталона они учебные, `# ВЗЯЛ` не должен считаться ошибкой; сами комментарии
  остаются видны серым;
- «без пробелов» (включено) не различает `lo+(hi-lo)//2` и `lo + (hi - lo) // 2`;
- отступ сравнивается всегда, но относительный: сдвиг всей функции целиком
  ошибкой не считается, а съехавшая внутрь блока строка — считается;
- строки сопоставляются через LCS, а внутри блока несовпадений пары
  подбираются по похожести, а не по порядку — лишняя строка не сдвигает
  все остальные в «отличается».

Имена переменных не нормализуются: `l` вместо `left` покажется как отличие.
Это нарочно — дрилл про форму шаблона, и расхождение лучше видеть.

## Редактор

Подсветка синтаксиса прямо в поле ввода: под кареткой лежит подсвеченный слой,
метрики у него совпадают с textarea до пикселя. Правки идут через
`execCommand("insertText")`, поэтому нативный Ctrl+Z продолжает работать.

Кнопка `python` / `typescript` в панели переключает язык редактирования —
подсветку, символ комментария и шаг отступа. Тесты в любом случае гоняет
python: дриллы написаны на нём, а ts-режим нужен, когда переписываешь шаблон
на другой язык.

| | python | typescript |
|---|---|---|
| шаг отступа | 4 пробела | 2 пробела |
| комментарий | `#` | `//` |
| отступ после | `:` | `{`, `(`, `[` |
| дедент следующей строки | `return`, `pass`, `break`, `continue`, `raise` | — |

Что умеет:

- **Enter** — держит отступ, добавляет уровень после `:` (или `{` в ts)
  и снимает его после `return` / `pass` / `break`;
- **Enter между парой скобок** — раскрывает их в три строки с курсором внутри;
- **Tab / Shift+Tab** — сдвиг выделенных строк целиком; без выделения Tab
  доводит до ближайшей позиции табуляции, а не всегда вставляет 4 пробела;
- **Backspace** в отступе снимает уровень целиком, а между пустыми скобками
  или кавычками удаляет обе;
- **скобки и кавычки** закрываются сами; выделил кусок и нажал `(` или `"` —
  обернуло; закрывающая скобка не дублируется, а проскакивает уже стоящую;
- **⌘/Ctrl + /** — закомментировать или раскомментировать выделенные строки;
- **⌘/Ctrl + Enter** — запуск тестов.

## Что переживает перезагрузку

Всё состояние лежит в localStorage браузера и восстанавливается при следующем
открытии страницы:

- открытый шаблон (он же в адресе после `#`, ссылкой можно делиться),
  активная вкладка (теория / дрилл) и выбранная функция;
- по функции на шаблон: какую дриллил последней — вернёшься к шаблону,
  откроется она же;
- черновик кода отдельно для каждой функции и история попыток (время, ✓/✗);
- прокрутка теории и режим «исходник markdown»;
- таймер: если он шёл, то после перезагрузки идёт дальше и добирает время,
  прошедшее между закрытием и открытием. Если перерыв больше получаса,
  считается, что сессия брошена: время сохраняется, но таймер стоит на паузе.

## Как это устроено

Отдельной базы нет: сервер парсит `ethalons/blockN/*-ethalon.py` и
`drill/blockN/*-drill.py` через `ast` при каждом запросе. Добавил новый
шаблон в тех же соглашениях — он появится в интерфейсе сам:

- имя файла `<имя>-ethalon.py` и `<имя>-drill.py` в одноимённых `blockN`;
- первая строка докстроки модуля: `ШАБЛОН <номер> — <название>`;
- блок `# ===...` над функцией — её разбор (в дрилле — задание);
- тест для функции `foo` называется `test_foo`;
- целью дрилла считается функция, у которой в эталоне есть `test_<имя>`,
  остальные (`TreeNode`, `build`, `is_valid_order`, `norm_sets`) —
  вспомогательные. Поэтому можно писать решения прямо в `-drill.py`:
  функция не пропадёт из тренажёра оттого, что в ней больше нет `pass`.
- целей у каждого шаблона ровно 4, и порядок в файле — это номер группы:
  первая функция каждого шаблона — группа 1, вторая — группа 2 и так далее.
  День = одна группа по всем 18 шаблонам, на четвёртый день круг замыкается.
  Добавляешь шаблон — держи в нём те же 4 цели.

Код из редактора выполняется настоящим `python3` в отдельном процессе с
таймаутом 15 секунд. Сервер слушает только 127.0.0.1 и рассчитан на запуск
на своей машине.
